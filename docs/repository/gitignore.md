# Runtime and development exclusions

[Source](../../.gitignore) · [Index](../README.md)

The ignore file keeps generated student data and local development outputs out of
new Git changes. It does not delete files, encrypt them, or untrack previously
committed data.

| Pattern group | Examples and purpose |
| --- | --- |
| Interpreter caches | __pycache__, pyc/pyo and related generated bytecode |
| Environments | .venv*, venv, env, ENV |
| Test/tool state | pytest/mypy/ruff caches, coverage, tox/nox |
| Build outputs | build, dist, egg-info |
| Root output directories | output, ekpa_desktop, numeric account-root directories |
| Generated trees anywhere | course_*, lesson_*, test_[0-9]* including attachments and extracted code |
| Runtime record names | discovery/history/upload/download JSONL, CSVs/index, exercise.txt |
| Temporary/local logs | students_*.tmp and *.log |

A custom --output inside the repository is covered by generated directory/file
patterns once those files exist. Output outside the repository is outside Git's
working tree. Test Python filenames such as test_storage.py do not match the
numeric generated test-directory pattern. Documentation refers to runtime files
but does not create or track real student records.

Use `git check-ignore -v PATH` to investigate why a specific generated file is
ignored. New runtime artifacts should be added here when their writer is added;
changing this file does not replace a backup policy.
